Detailed Description

All methods, callbacks and destruction run on the session's state worker. The parent has already called observe(), owns the client, and must call drive() after native callback batches and after any model change (including changes from other contributions and refresh). Never drive or clean up inside a native callback. Dispatch each due retry to its source via retry(). The address-family flags select IPv4 and IPv6, in that order. Call cleanup() before removing the observation or freeing the client. On epoch invalidation cleanup still frees native objects; stale session errors can be returned because the session already released its leases. A drive/start/retry error is never a success indication: backend errors are reported even when their retry was scheduled. The parent must continue driving live contributions and route all IDs from takeDueRetries(). Native backend failures and SRV mismatches are considered recoverable; other failures are not. An exception during drive cleans up and terminates this owner; resource-limit and terminal session errors require parent teardown.

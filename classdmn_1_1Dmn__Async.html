Schedule a callable task to run after the given duration has elapsed.

The task will not be executed before the duration has passed. It may not execute precisely at the moment the duration elapses (scheduling is not real-time), but execution will occur at or after the specified time. Its handle's wait() rethrows exceptions from the task. Immediate tasks are processed first while a delayed task waits for its deadline. The worker waits for the deadline rather than repeatedly polling; queued immediate tasks retain priority over tasks awaiting their deadlines.

Parameters
durationTime to wait before executing the task.
funcThe callable task to execute asynchronously.
argsThe arguments to the callable task.
Exceptions
std::invalid_argumentif duration is negative.
std::overflow_errorif duration or its deadline cannot be represented by the steady clock.

Schedule a callable and return its eventual result as a future.

This has the same deadline conversion, rejection, queue backpressure, and worker scheduling semantics as addExecTaskAfterWithWait(). The returned future is single-consumer; destroying it does not cancel accepted work. Do not wait for it from this object's worker context. The callable's result must be void or an owned value; reference results are rejected at compile time. The callable and arguments are move-captured and invoked as rvalues, consistent with the other task APIs.

Same as addExecTaskAfter(), but returns a task wait object so the caller can block until the scheduled task finishes.

The task will not be executed before the duration has passed. It may not execute precisely at the moment the duration elapses (scheduling is not real-time), but execution will occur at or after the specified time.

The returned shared_ptr points to a Dmn_Async_Handle; calling wait() on it will block until the submitted task has finished. If the task throws an exception, wait() will rethrow it.

Submit a callable and return its eventual result as a future.

The task runs once on this object's existing serialized worker. Its result or exception becomes available through the returned single-consumer future. This call does not wait for task completion, but enqueueing retains the existing pipe's backpressure behavior. Destroying the future does not cancel accepted work. Do not wait for this future from this object's worker context, as that would prevent the queued task from running.

The callable's result must be void or an owned value; reference results are rejected at compile time. The callable and arguments are move-captured and invoked as rvalues, consistent with the other task APIs.

funcThe callable task to execute asynchronously.
argsThe arguments owned by the submitted task.
Returns
A future containing the callable's value, or void.
